# Общие рекомендации по 2 лабе
### Порядок действий:

1. Строим конечный детерминированный автомат и согласовываем его
    1. Чем быстрее - тем лучше, его **обязательно** надо согласовывать, на это может уйти несколько попыток
    2. В идеале не более 15 состояний (если больше - посоветуйтесь, задолбаетесь кодировать)
    3. Можно делать переходы по нескольким кнопкам (например S0 -> (a, b) -> S1)
        1. Не советую по a менять количество минут-часов и тд, там свои особенности в схемотехнике
    4. Кнопок не более 4 
    5. Подумайте сразу, какие микрокоманды (выходы) будут импульсными, какие - потенциальными, обсудите в случае затруднения
        1. Импульсные обычно - сброс, увеличение минут-часов, смена am-pm
        2. Потенциальные - отображение часов, минут, останов, старт ... 
2. Аналитика
    1. Кодируем все состояния (должны уложиться в 3-4 бита), выходы и кнопки-входы (тут 2 бита)
    1. Строим таблицу переходов и выходов по **согласованному** конечному автомату 
    2. Выбрасываем часть с выходами, по переходам строим двоично-кодированную таблицу переходов по кнопкам: текущее состояние общее для каждого состояния, следующее - куда ведет конкретная кнопка
    3. Минимизируем с помощью [карт Карно](https://sublime.tools/ru/karta-karno/). Если состояний меньше 15 - неиспользуемые можно пометить X, как неопределенное состояние

    (*дальше советую перейти к схемотехнике, сделать управляющее устройство и проверить, что вы сделали переходы между состояниями правильно. Потом вернетесь*)

    4. Строим таблицы истинности для потенциальных и импульсных микрокоманд. 
        1. Потенциальные - оставляем только состояния и думаем, в каком состоянии какая потенциальная микрокоманда работает
        2. Импульсные - копируем двоично-кодированную таблицу переходов, оставляем только текущее состояние и **по кнопкам** смотрим, какие импульсные микрокоманды в конкретном состоянии становятся активными.
    5. Минимизируем или картами Карно, или по вектору (в интернете много подобных сайтов)  

    (*самый нудный этап все, но если видите некорректное поведение - идите снова проверять таблицы*)
3. Схемотехника: общие рекомендации
    1. Не мучайтесь с семисегментными индикаторами, берите шестнадцатиричные для цифр
    2. В идеале (если вариант не с отображением секунд) - 4 индикатора
    3. В качестве музыки можно просто использовать лампочку, а не пищалку. Рядышком можно приткнуть индикатор, где отображается номер мелодии (если есть)
    4. Тактовый генератор должен быть **один**
    5. Для удобства рекомендую использовать тоннели
    6. Если есть будильник - хорошо бы вывести лампочку, которая показывает, включен он или выключен
    7. Таблицы можно напрямую загружать в логисим, но делать минимизацию для отчета вам все равно придется

4. Схемотехника: все еще  
    1. Для обновления состояния можно использовать D-триггер, где на тактовом входе будет флаг, который срабатывает при нажатии любой кнопки
    2. Для отображения минут, секунд и часов следует использовать счетчики. Причем начинать нужно от тактового генератора всегда с секунд, постепенно движась к более старшим разрядам (сек ед, сек дес, мин единицы и тд). Основные ошибки - следите за максимальным значением (после 9 идет 0), срабатывание (задний-передний фронт, экспериментируйте). Не забывайте про вход Reset для сброса значений. 
    3. Формируйте команды по смене минут часов таким образом, чтобы они не затрагивали никакие другие модули (при корректировке минут времени - часы не должны меняться даже при переходе 59-0, в будильнике тоже ничего не должно меняться и наоборот)
    4. Чтобы регулировать, что именно на индикаторах отображается, используйте мультиплексоры, где на выбирающий вход подается потенциальная команда
